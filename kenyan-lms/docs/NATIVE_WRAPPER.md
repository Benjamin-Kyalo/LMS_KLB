# Native app wrapper (Capacitor)

The browser PWA remains the primary client. Capacitor is included as a thin
wrapper around the **same React build** so a future store build does not need a
second frontend codebase.

## What is in the repository

- `frontend/capacitor.config.ts` — app id, app name and `webDir: "dist"`.
- `frontend/package.json` — pinned Capacitor packages and `mobile:*`/`cap:*`
  scripts.
- the service worker generated by `vite-plugin-pwa` — keeps offline reading and
  queued writes available in the wrapper too.

No native platform projects, signing keys, provisioning profiles or API
credentials are bundled.

## Local wrapper build

From `frontend/`:

```bash
npm install
npm run mobile:sync
```

`mobile:sync` runs `npm run build` then `cap sync`, copying the PWA output into
any scaffolded native projects. To create those projects (requires local
platform tooling):

```bash
npx cap add android   # needs Android SDK / Android Studio
npx cap add ios       # needs macOS and Xcode
npm run cap:open:android
npm run cap:open:ios
```

For live development against a local Vite server, set shell variables before
the command (do not commit host-specific values):

```powershell
$env:CAPACITOR_SERVER_URL = "http://192.168.1.10:5173"
$env:CAPACITOR_CLEARTEXT = "true"   # local HTTP only; never use in production
npm run cap:sync
```

Production builds should use the packaged `dist/` output and an HTTPS API
configured through `VITE_API_BASE_URL` at build time.

## What this does **not** provide

- No signed APK or IPA can be produced in this environment; Android SDK, macOS
  Xcode, signing identities and store accounts are required.
- No physical-device testing has been performed. Only desktop and emulated
  mobile browser checks were run.
- No native plugins, push notifications, app-store listings, screenshot sets or
  store review artefacts are included.
- No credentials, keystore, provisioning profile or third-party SDK keys are
  bundled.
- The wrapper is not a reason to call Phase 7 or Phase 9 complete.

Treat the wrapper as build scaffolding plus documented steps, not as a shipped
native app.
